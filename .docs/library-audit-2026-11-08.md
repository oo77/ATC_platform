# Библиотека: аудит прав, просмотров и обновление

**Дата:** 2026-11-08

## Найденные проблемы

### Права доступа и безопасность

| # | Проблема | Последствие | Исправление |
|---|----------|-------------|-------------|
| 1 | Каталог проверял доступ только по `user_id` и `role_name`, а открытие книги — ещё по группе и курсу | Книгу, выданную группе/курсу, можно было открыть по ссылке, но не найти в каталоге | Единые правила доступа в `server/utils/libraryAccess.ts` для каталога, чтения, обложек и авторов |
| 2 | `PATCH /admin/books/[id]` проверял право `"library.manage"` (в системе — `library:manage`) и делал `parseInt` от UUID | Редактирование книг всегда отвечало 403 | Переписан эндпоинт: правильное право, UUID, валидация языка/года, журнал |
| 3 | Выдача доступа группе читала несуществующую таблицу `group_students` | Выдача группе падала с 500 | Группа и курс хранятся одной записью (`group_id`/`course_id`), новые слушатели получают доступ автоматически |
| 4 | Выдача пользователю делала `parseInt` от UUID пользователя | Личная выдача из модалки книги не работала | Общий сервис `server/services/libraryAccessService.ts` с проверкой получателя |
| 5 | Обложки отдавались без проверки доступа и с `Cache-Control: public` | Первую страницу любой книги мог получить любой вошедший пользователь, а прокси — закэшировать | Обложка — только при доступе к книге, `private` |
| 6 | PDF отдавался по прямой ссылке при любой «открытой» сессии | Ссылку можно было использовать в обход ридера | Файл выдаётся только по токену активной сессии своего пользователя, `no-store` |
| 7 | Сессии чтения не закрывались при закрытии вкладки | «Вечные» сессии блокировали удаление книги и отзыв доступа | Сессия активна только при heartbeat за последние 10 минут; зависшие закрываются автоматически |
| 8 | Отзыв доступа запрещался, пока книга «открыта» | Доступ нельзя было забрать | Отзыв сразу; ридер получает 403 на следующем heartbeat (≤ 30 с) и закрывает книгу |
| 9 | Список авторов отдавался по всему фонду | Читатель видел авторов недоступных книг | Только авторы доступных книг |
| 10 | Роль при выдаче не проверялась, `limit` каталога не ограничен, ошибки БД уходили клиенту | Мусорные записи, тяжёлые запросы, утечка деталей | Валидация роли, `limit ≤ 48/100`, общие сообщения об ошибках |
| 11 | Загрузка принимала любой файл с расширением `.pdf` | Не-PDF ломал обработку | Проверка сигнатуры `%PDF-`, лимит 200 МБ |
| 12 | Токен сессии `uuid+uuid` (72 символа) в колонке `VARCHAR(64)` | Риск ошибки вставки | 64 hex-символа из `crypto.randomBytes` |
| 13 | `expires_at` (TIMESTAMP) не принимает даты после 2038 | Выдача «до 2099» падала с 500 | Валидация: не позже 31.12.2037 |
| 14 | Действия с библиотекой не попадали в журнал (`LIBRARY_BOOK` пропал из enum в миграции 033) | Нет аудита выдач и удалений | Миграция 053 возвращает значение; журналируются выдача, отзыв, правка, загрузка, удаление, экспорт, открытие книги |

### Просмотры и аналитика

- Время чтения считалось как «конец − начало сессии» — вкладка, открытая на ночь, давала часы чтения. Теперь время копится по heartbeat, только пока вкладка видима, простой > 2 минут не засчитывается.
- Завершение книги определялось по последней странице: вернулся к началу — «не дочитал». Теперь хранится `max_page` и `completed_at`.
- Число читателей в списке считалось по сессиям, а не по прогрессу.
- Добавлены: аналитика библиотеки (`GET /api/library/admin/analytics`) и расширенная аналитика книги — динамика по дням, распределение прогресса, читатели, тренды к прошлому периоду, «требует внимания».

### Ридер

- Ошибка `const progressSaveTimeout` — прогресс страницы не сохранялся вовсе.
- PDF скачивался целиком до показа первой страницы; воркер pdf.js грузился с jsdelivr.

## Что сделано

- **Каталог** (`/library`): «Продолжить чтение», личная статистика, полки (все / читаю / прочитанные / не начатые), обложки (первая страница PDF, ленивый рендер), сетка/список, сортировки, срок доступа и бейджи на карточках.
- **Ридер** (`/library/[id]`): загрузка частями (HTTP Range), предзагрузка соседних страниц, ограничение размера canvas, «по странице / по ширине», миниатюры, ползунок, ночной режим, горячие клавиши, свайпы, автоскрытие панелей, корректные экраны ошибок и отзыва доступа, `sendBeacon` при закрытии.
- **Панель управления** (`/admin/library/books`): вкладки «Книги» / «Аналитика», фильтр «без доступа», колонки доступа и читателей (в т.ч. «читают сейчас»), обложки, сортировки; модалка доступа с поиском получателей на сервере (человек / группа / курс / роль) и сроком; массовая выдача со сроком.

## Изменения API

- Новые: `GET /api/library/admin/analytics`, `GET /api/library/admin/recipients`.
- Удалены: `GET /reading/[bookId]/page/[n]` (серверный рендер давно отключён), `DELETE /admin/books/[id]/access/[userId]` (не использовался, логика была сломана).
- `POST /reading/[bookId]/start` возвращает `token`; `raw`, `progress`, `end` требуют его.
- `POST /reading/[bookId]/progress` — тело `{ token, page, visible }`.
- Выдача доступа — тело `{ type, targetId, expiresAt }` (старые поля `userId`/`groupId`/`roleName` поддерживаются).

## Перенос проекта на другую машину

В `books.original_file_path` хранится абсолютный путь с машины, где книгу загрузили. `getBookById` теперь
проверяет этот путь и, если файла там нет, ищет его по имени в `storage/library/originals` текущего проекта
(`resolveBookFilePath` в `server/utils/pdfProcessor.ts`). Достаточно скопировать папку `storage` вместе с кодом —
править пути в БД не нужно. Обложки и так ищутся по ID книги в `storage/library/covers`.
